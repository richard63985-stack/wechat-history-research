# 报告契约

## 交付物

至少交付：

1. SQLite 历史语料库；
2. manifest JSON；
3. 可检查的结构化 artifact/JSON；
4. 结论化 HTML；
5. 与 HTML 同版的 PDF。

若用户需要日常检索，再额外提供 CSV、Markdown 或 Obsidian 索引；不要默认制造第二套事实源。

## 正文结构

报告按结论链组织，而不是按处理步骤组织：

1. 核心结论；
2. 历史演进与稳定框架；
3. 主题地图；
4. 最近 12 个月观点变化；
5. 当年分阶段总结；
6. 市场/事实验证（仅在执行时保留）；
7. 核心观点时间线；
8. 公司、机构与产品索引；
9. 可提炼的研究规则；
10. 样本、方法、来源与限制。

HTML 对上述章节使用稳定的 `data-section`：`executive-summary`、`history-evolution`、`theme-map`、`recent-changes`、`current-period`、`market-validation`、`timeline`、`entity-index`、`research-rules`、`methodology`。未执行市场验证时可省略 `market-validation`。

## 表达要求

- 开头先给总判断，再给证据。
- 用“文章/转载机构认为”“作者选择强调”“本次研究判断”区分归属。
- 用完整句子表达结论，不把原始摘要、关键词列表或模型备注直接贴入正文。
- 市场价格只说明发布后的同向/反向表现，不写成因果证明或账号正确率。
- 方法和限制集中在附录；正文不出现工作安排、未完成问题清单或对用户的操作建议。
- 总量核对通过代表当前渠道目录完整，不自动代表账号绝对全历史；优先写“当前可访问 N 篇”。

## 数字一致性

以下数字必须在数据库、manifest、artifact、HTML 和 PDF 中一致：

- 唯一文章数与内容等级拆分；
- 最早/最晚发布日期；
- 最近 12 个月与此前 12 个月样本数；
- 主题和实体统计分母；
- 时间线节点数和阶段文章数；
- 市场验证总数、背景数、成熟窗口数和时间不足数。

## PDF 验收

从最终 PDF 重新渲染全部页面，不复用旧预览。逐页确认：

- 封面、章节起始、表格续页和附录没有异常空白；
- 文字、图表、链接、页码和页脚没有裁切；
- 中文文本层可复制，标题和关键数字可搜索；
- 页面尺寸和方向一致；
- PDF 未加密，元数据标题正确；
- HTML 中的文章链接在 PDF 中保留为可点击注释。

视觉检查通过后，再运行文本层、页数、链接数量和关键数字检查。最终向用户只链接 `outputs/` 中的交付文件，过程文件留在 `work/`。
