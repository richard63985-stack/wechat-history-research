# 目录、阅读副本与增量更新

在开始归档、导出阅读包或增量更新前阅读本文件。一个公众号使用一个研究目录；多个公众号并列存放，用名称加稳定账号标识区分。研究目录与 Skill 安装目录、公开代码仓库分开。

## 固定目录

```text
公众号研究目录/
├── index.md                         人类入口，链接最新已验收批次与历史批次
├── work/
│   ├── data/archive.sqlite          持续更新的主数据库
│   ├── data/manifest.json           当前采集范围与状态
│   ├── raw/<采集批次>/              脱敏后的原始目录/正文响应
│   └── tmp/                         临时文件、打印配置和校验预览
├── outputs/<交付批次>/
│   ├── index.md                     本批次入口，按月目录、Excel、报告与数据链接
│   ├── overview.xlsx                总览＋可筛选的逐篇审阅目录
│   ├── articles/YYYY/MM/
│   │   ├── index.md                 本月文章列表
│   │   └── YYYY-MM-DD_标题__短ID.md  每个文章 ID 一份阅读文件
│   ├── articles/undated/            日期缺失时使用，不推测发布日期
│   ├── data/
│   │   ├── archive.sqlite           本批次只读用途的数据库快照
│   │   ├── manifest.json            本批次样本清单
│   │   ├── reading.json             Excel 输入及 ID→MD 路径/校验值清单
│   │   └── index.json               研究层结构化索引（若已完成分析）
│   └── reports/                     同一版报告 HTML、PDF 与 artifact JSON
└── notes/                           用户批注；有需要时才建立
```

批次使用生成时间或宿主要求的唯一标识，冲突时新建批次。只有实际产生内容时才建目录；仅导出历史数据时不重新生成研究报告。旧项目无需强制搬迁：在入口标明现有数据库位置，后续新交付遵循此结构。

`work/data` 是继续采集和分析的主库；`outputs` 内数据库是特定批次的快照，避免旧报告因主库更新失去可复核性。SQLite、MD、Excel、JSON 都放在本地，不因 Skill 公开而公开内容。

## Markdown 与 index.md

- 每条目录记录都导出一个 MD，包括仅摘要、仅目录和失败记录；缺文页清楚说明证据不足，不能把提炼摘要填入“原文正文”。
- 文件头保存稳定文章 ID、公众号、发布日期、原文链接和内容等级。页面按“基本信息 → 已有研究提炼（非原文）→ 采集正文/来源摘要/缺文说明”组织。
- 默认导出数据库中的正文文字，不自动补图或复原原网页版式；如另有图片归档，在同批次内用相对路径引用。
- 文件名清除 Windows 非法字符、控制字符与末尾空格/点；标题截到 36 字符，完整标题保留在文件内。日期加标题后附账号/文章 ID 的 12 位哈希，避免同日同名冲突。仍有路径冲突时停止，不覆盖。
- 目录按 `YYYY/MM` 分层，月份内按发布时间倒序。使用 UTF-8 和相对链接，链接中的特殊字符正确编码，移动整个批次仍可阅读。
- 批次 `index.md` 链接 Excel、数据库、研究索引、报告及各月目录。月目录链接每篇 MD，MD 可返回月目录。
- 研究根目录 `index.md` 指向最新**已验收**批次并保留历史入口。更新已有入口时保留人工内容；只改本 Skill 管理的链接区。它不是 GitHub 仓库的 README。

## Excel 总览

默认两张表即可：

1. **总览**：文章总量、全文/摘要/目录拆分、全文覆盖率、日期范围、按月数量、审阅进度及使用说明；由目录单元格公式计算汇总。
2. **文章目录**：发布日期、完整标题、内容等级、主主题、研究摘要、核心观点、实体、本地 MD 链接、原文 URL、审阅状态、审阅备注、稳定 ID、正文字数与相对路径。

日期和数量保留为可排序的真实类型；冻结标题行与日期/标题列，启用筛选。摘要/观点长文本允许显示明确标注的预览，完整内容在 MD。人工状态/批注列使用独立底色，状态提供选项。原文字符串按文本写入，不能被当作 Excel 公式执行。

Excel 超链接使用相对 MD 路径，原文 URL 另列明文。Excel、系统关联程序可能提示确认打开本地文件；整包移动后检查链接，而不是绕过安全提示。批注不会自动写回 SQLite。

可选 `build_overview.mjs` 示例的已测宿主不在预览中计算 `HYPERLINK`，因此用 `IFERROR` 显示“打开MD”，由 Excel 打开后执行原生链接。该宿主的 XLSX 导出也可能不保留冻结窗格；这不是所有表格工具共有的限制。无论使用哪种工具，都必须检查实际导出文件，如缺失则在交付中说明，可在 Excel 的“视图 → 冻结窗格”手动设置，不能仅凭脚本调用宣称已冻结。

## 执行

导出脚本仅依赖 Python 标准库，兼容当前数据契约及旧版 `mp_name/body_status` 结构；旧版通过可用正文/摘要判断内容等级，源库不改字段。

```text
python scripts/export_reading.py --db <主库.sqlite> --out <新的批次目录>
python scripts/export_reading.py --self-check
```

展示日期默认 UTC+08:00，可用 `--utc-offset` 指定其他固定偏移，不依赖操作系统时区。脚本创建数据库快照、manifest、逐篇 MD、月目录、批次入口和 `reading.json`，**不生成 Excel 或研究报告**。批次入口中的 Excel 链接在下一步完成后才有效。

用所在环境已有的表格工具或 XLSX 库，将 `reading.json` 生成为 `overview.xlsx`，遵循上述字段、公式安全、相对链接和验收要求。`reading.json` 是共用输入，不要求某个特定平台或库。

**可选示例**：仅当宿主实际提供 Node.js 和 `@oai/artifact-tool` 时，复用 `scripts/build_overview.mjs`：

```text
node build_overview.mjs <批次>/data/reading.json <批次>/overview.xlsx <临时预览目录>
```

使用此示例时，把 builder 复制到本次 `work/tmp` 下的运行目录，按宿主返回的依赖位置建立 `node_modules` 软链接或 Windows junction。不要把该依赖目录放入公开仓库，也不要假定私有包可从 npm 安装。没有该依赖时直接使用当前环境的其他表格工具，不必安装 Codex；如果没有可用替代工具，保留已完成的 MD，明确 Excel 尚未交付，按环境审批流程补齐。有表格技能时按其验收要求执行。

## 增量与验收

- 采集按稳定 ID 更新主库，只补新增/缺失记录；阅读包每次生成独立完整快照。数百篇规模下全量重新导出能减少漏文、旧链接和批注覆盖风险；不要把新旧批次混写。
- 导出脚本拒绝写入已存在的批次目录。若失败留下未完成批次，保留用于诊断，以新批次重试；不要覆盖或删除用户已批注文件。
- 原始响应按采集批次追加，保留采集时间。认证状态、Cookie、临时浏览器配置不进入交付包。
- 验收按 ID 对齐：数据库记录数＝文章 MD 数（不含目录 index）＝Excel 目录行数＝`reading.json` 记录数；内容等级拆分、发布日期和原文链接一致。
- 检查全部相对链接、文件名跨平台合法性、MD 内容校验值及来源正文对应关系；验证同名文章、无日期、缺文页和重复运行拒绝覆盖。
- Excel 检查公式、筛选、日期格式、冻结区域和两张工作表的视觉效果；再将已有报告/研究索引放入对应位置并补齐批次入口。Windows 链接或完整流程未实机测试时明确说明。
- 数据与导出验收不等于重新核实原文事实或研究结论。交付之后才更新研究根目录的最新批次链接。
